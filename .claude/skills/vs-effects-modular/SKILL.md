# Changing or adding an effect

## Task
Edit an effect, change a settings default, or add a new effect, keeping the effect folder, its section in `docs/EFFECTS.md` and the shipped defaults in step.

## Prerequisites
- Layout (2026-11-02, README and index merged into docs/EFFECTS.md 2026-11-25): `src/effects/<Name>/` holds the effect's C++,
  `defaults.toml` and `SHADERS.txt` (its shader files; the shaders themselves stay in `src/hlsl/NewVegas/`, mirroring the game's
  `Shaders\VegasShaders\` layout). What the effect's README used to hold (what it does, inputs, settings, passes, edge cases, Vulkan
  path, what correct/wrong looks like) is its `## <Name>` section in `docs/EFFECTS.md`, with the index table at the top, generated by
  `tools/effects_index.py` (`check` verifies it).
- **Read the effect's section in `docs/EFFECTS.md` first.** A stale doc is worse than none.
- Deferred first (repo `CLAUDE.md`, "Product rules"): say which path (deferred or forward) the change uses and why.

## Steps
1. **Change the effect** (code and shaders); update its section in `docs/EFFECTS.md` in the same change.
2. **Settings defaults.** `resource\VegasShaders.defaults.toml` is what ships; a key missing from it is not read. Edit the fragment
   (`src/effects/<Name>/defaults.toml`, or `resource/defaults/<Name>.toml` / `Core.toml` for sections without an effect folder),
   then `py -3.10 -I tools/defaults_tool.py merge .`. A new section also needs its line in `resource/defaults/ORDER.txt`.
3. **A changed default players may have saved:** add a migration step in `Configuration::UpdateOldDefaults()`
   (`src\core\SettingManager.cpp`) and raise the settings version (the menu's Save writes every key). A feature that works ships on
   by default.
4. **A new effect:** a step in `src/core/EffectChain.cpp` (two ordered step tables, pre- and post-tonemap), a member in
   `ShaderManager` (Effects struct + registration), its folder, its section in `docs/EFFECTS.md`; regenerate the index with `tools/effects_index.py`.
5. **Effect constants:** `EffectRecord` binds an effect's `TESR_` parameters (constants and samplers) by DECLARATION ORDER in the
   `.fx` file; a `register()` on them is ignored (`src/core/EffectRecord.cpp`).

## Validation
- `py -3.10 -I tools/defaults_tool.py check .` passes (the project hook `.claude/hooks/defaults-check.ps1` runs it after an edit to
  a fragment or ORDER.txt).
- Offline shader checks and a build: skill `vs-build-deploy`.
- `docs/EFFECTS.md` section updated in the same diff; a changed default has its migration and a higher version.

## Troubleshooting
- A key is ignored in game: it is missing from the merged `resource/VegasShaders.defaults.toml` (run `merge`).
- A constant reads 0 in an effect: it is not a `TESR_` name registered in C++, or the declaration order moved.
- `check` fails after merging branches: both sides added a line; keep one (a duplicate default once made a merged file fail to load
  in game).
